# Career Track V3

The active browser entry is `src/bootstrap.js`, which lazily imports `src/v3/workspace.js`. The implementation retains vanilla ES modules and esbuild. No Google or Supabase browser client is initialized. The existing backend and v2 modules are retained as inactive, tested compatibility code.

`data/v3/` separates source provenance, funding opportunities, universities, programmes, deadline dependencies, country policies, research groups, firsthand experiences and reviewed changes. `schema.js` validates identifiers, links, references, window metadata and acyclic deadline dependencies. `catalog.js` builds canonical lookup maps and normalized search text once. The initial registry is curated, not exhaustive. Legacy route IDs and the original 102 progress keys remain stable.

`domain.js` independently evaluates the application window, eligibility, funding classification, decision, personal stage and lifecycle. Urgency is an additional flag on an open window. Registry-wide totals are calculated before filtering/pagination; submitted, archived and not-pursuing records never change the global open total. The next-action view excludes final/submitted work, expired prerequisites and unresolved required nomination/EOI stages. International-only restrictions do not disappear into a preference score.

`store.js` stores private data under `career-track:v3`. Applications use `opportunity:intake` keys; university admissions use `programme:intake`; annual budgets add a year index. Documents, referees, personal blockers, profile and preferences are private device state. A v2 workspace is read into memory, validated and presented read-only until the user downloads a backup. Migration saves a raw pre-migration copy before the first V3 write and never changes the original v2 key. Corrupt state blocks edits and remains exportable; recovery preserves original bytes. Failed writes retain in-memory drafts and Retry. Concurrent-tab writes are reread before unrelated mutations; failed local drafts are never discarded by a storage event.

The controller renders the active view only, preserves note drafts, and uses a single interval for visible timers. Explorer filters, search, page and intake are URL-restorable. One normalized route drives each guide, pipeline item and country/university link. Native controls/dialogs preserve keyboard behavior. Static source text and private notes are escaped; links require safe HTTPS URLs. Public research pages are never scraped by visitors.

The build emits a content-versioned service worker for the static app shell and assets. It caches no API responses, private state or exports. Previously loaded source data remains usable offline; cache refresh happens on a later service-worker activation. Device storage and backups remain independent of the static cache. Source monitoring uses an actual daily GitHub Actions schedule with robots checks, bounded retrieval and a report artifact. Fingerprints are change candidates, not verified facts. A maintainer reviews primary sources before changing claims; private-repository reports can be imported into the local Sources view.

Calendar exports include verified exact instants and date-only all-day markers. Only exact instants carry alarms. Unknown/tentative dates are excluded; relative-rule dates are labeled as derived. Importing a calendar file into a calendar app is required for reminders outside the browser. No live exchange-rate feed, automatic visa advice, provider application submission or referee messaging is claimed.
